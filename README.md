# DEAD OR ALIVE（仮）— Ver.0.3 MVP

2人用の心理戦カードゲームのプレイ可能なプロトタイプです。Flutter Web で動作し、スマホ表示にも対応します。
オンライン対戦・課金・広告・外部バックエンドは実装していません（プレイヤー対 CPU）。

設計の考え方は **`DESIGN.md`** に、Ver.0.2 からの経緯はコミット履歴にまとまっています。

---

## ゲームの核

> **中央に伏せた9枚を巡り、「自分だけが一部の正体を知っている」情報差を武器に、
> 善人を生かすか殺すかを争う心理戦。**

- 中央に **善人3・悪人3・中立3** の9枚を3×3で伏せて置く（数字1〜9を一意にランダム）。
- 開始時、**あなたと CPU はそれぞれ異なる3枚の正体だけ**を知る（残り3枚は誰も知らない）。
- **正体（種類・数字）は終了時まで非公開。** 見えるのは状態（生存/死亡/封印）と、公開される行動履歴だけ。
- 相手の行動（どの位置に・どの効果・どの数字・成否）から、伏せられた正体を推理する。

## 役割

- **救済者**：善人を生存させる（生存善人=2点、死亡悪人/中立=1点）
- **執行者**：善人を死亡させる（死亡善人=2点、生存悪人/中立=1点）

中立は「自分の本能どおり」に扱うと相手の得点になる（救済者が中立を生存＝執行者に加点、執行者が中立を死亡＝救済者に加点）。

## 生死カードと判定

- 効果：**デッド**（死亡）/ **アライブ**（生存・復活）/ **シール**（封印＝終了まで状態固定、各自1回）。
- パワー判定：`生死カードの数字 ≧ 対象の数字` で成功。
- **失敗しても正体は非公開。** 「そのパワーでは倒せなかった」＝対象は使った数字+1以上、という推理材料だけが残る。

## 手番・手札

- 弱い役（現状は救済者）に **先手・最終手番・+1枚** を与えて役職差を補正（総手番は奇数）。
- 手札は両者同一の固定配分（引き運を排除）。弱い役7枚 / 強い役6枚。
- 全手番を消化したら正体を一斉公開して得点集計、高い方の勝ち（同点は引き分け）。

## セットアップ / 起動 / テスト

```bash
flutter pub get

# Web で起動
flutter run -d chrome
# もしくはビルド（GitHub Pages 等の静的配信用。CDN 非依存で canvaskit を同梱）
flutter build web --release --base-href /d_o_a_test/ --no-web-resources-cdn

# 静的解析・テスト
flutter analyze
flutter test
```

動作確認は **Flutter 3.44.7 / Dart 3.12.2**。スマホ幅（320px 程度）でも縦スクロールなしで1画面に収まるようにしています。

## 現時点の検証結果（sim 6000 戦）

- **情報アドバンテージ：情報あり 82% vs 情報なし 17%**
  → **推理（情報差）が勝敗に強く効いている＝核が機能している。** MVP の最重要検証はクリア。
- **役職バランスは執行者有利**（救済者 約22% / 執行者 約52% / 引き分け 約26%）。
  善人=2点を能動的に狩る執行者は「集中3枚」を狙えばよく、救済者は「分散6枚＋防衛」で1手の価値が半分。
  これは**得点モデルの構造的な非対称**で、テンポ補正や係数微調整だけでは埋まらないことを確認済み（要・得点モデルの再設計判断）。

## 実装の構成

ゲームルール（domain / application）と UI（presentation）を分離。ルール数値は
`lib/features/game/domain/game_constants.dart` に集約。

```
lib/
  app/            … MaterialApp / router / theme
  features/
    title/ faction_select/(役割選択) rules/ result/
    game/
      domain/         … PersonCard, LifeDeathCard, PublicAction, GameState, GameResult, enums 等
      application/    … GameSetupService / GameRuleService / GameEngine / CpuStrategy / GameController
      presentation/   … ゲーム画面（中央3×3の共有場）と関連ウィジェット
  shared/           … カード描画ウィジェット / アイコン・色ヘルパ
tool/balance_sim.dart … バランス検証スクリプト
DESIGN.md            … Ver.0.3 設計ドキュメント
```

## テスト対象

- パワー判定 / デッド・アライブ・シール / 封印の恒久固定
- 得点集計（救済者・執行者・引き分け・開始時6-6）
- セットアップ（3/3/3・数字1〜9一意・秘密情報3+3・手札7/6）
- エンジン（弱い役先手・公開履歴に正体を含めない・終了判定）
- CPU（封印済みを狙わない・常に有効手）
- 1試合の通しプレイ / 画面遷移（タイトル→役割→ゲーム）

## 簡略化した点・今後

- MVP のため特殊能力なし・シールは各自1回・中立は得点のみ（破棄ペナルティなし）。
- **役職バランスの是正**（得点モデルの再設計 or 目標の再定義）が最大の残課題。
- CPU は公開履歴＋既知カードで推理する最小実装。性格の追加余地あり。
- 将来候補：スワップ、特殊能力、数字構成の調整、CPU 強化、リプレイ、チュートリアル、演出強化。
