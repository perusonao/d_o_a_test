# DEAD OR ALIVE（仮）

2人用の心理戦カードゲーム「DEAD OR ALIVE（仮）」の **プレイ可能なプロトタイプ** です。
Flutter Web で動作し、スマートフォン表示（画面幅 320px 程度）にも対応します。
オンライン対戦・課金・広告・外部バックエンドは実装していません（プレイヤー対 CPU の1試合完結型）。

---

## ゲーム概要

- プレイヤーはゲーム開始時に **善人陣営 / 悪人陣営** のどちらかを選びます。CPU は自動的に反対の陣営になります。
- 場には **人カード**（善人・悪人・中立、数字1〜9）が各プレイヤー9枚ずつ並びます。
- 手札の **生死カード**（デッド・アライブ・キープ、数字1〜9）を使い、相手の場の人カードの状態を変化させます。
- **善人陣営** … 終了時に「生存している善人」が「生存している悪人」より多ければ勝利。
- **悪人陣営** … 終了時に「生存している悪人」が「生存している善人」以上なら勝利（引き分けは悪人の勝ち）。
- 中立カードは勝敗人数に含まれませんが、陣営と逆方向の状態変化を成功させると **ペナルティ** を受けます。

## 現在のルール

### カード

- 人カード27枚（善人1-9 / 悪人1-9 / 中立1-9）。ID・種類・数字・状態・情報公開状態・防御状態・所有者を持つ。
- 生死カード（デッド / アライブ / キープ、各数字1-9）。ID・効果・数字・使用済みフラグを持つ。

### セットアップ（プロトタイプ）

- 人カード27枚をシャッフルし、プレイヤーと CPU に **9枚ずつ** 配布（残り9枚は不使用）。
- プレイヤーは自分の場の種類と数字を確認可能。CPU 側は裏向き表示（公開状態に応じて開示）。
- 生死カードは各プレイヤーに **9枚** 配布。デッド・アライブ・キープを **最低2枚ずつ保証**、残り3枚はランダム。

### ターン進行

1. 手札から生死カードを1枚選択
2. CPU 側の人カードを1枚選択（同じカードを再タップで選択解除）
3. 決定ボタンで効果判定 → 結果表示 → CPU ターンへ
4. 無効な操作は画面下部のメッセージで理由を表示

### パワー判定

`生死カードの数字 >= 人カードの数字` なら成功。

### 効果

- **デッド** … 成功で対象を dead（alive でも dead に）。失敗で変化なし。
- **アライブ** … 成功で対象を alive（dead なら復活。alive でも成功扱い・変化なし）。失敗で変化なし。
- **キープ** … 成功で1回分の防御を付与。防御中に次のデッド/アライブを受けると無効化し防御解除（永久固定ではない）。

### 情報公開

- 成功 … 対象の **種類と数字** を公開。
- 失敗 … 対象の **数字のみ** 公開（種類は「？」）。
- 一度公開された情報は隠さない。CPU 側カードのみ表示に反映（プレイヤー側は本人に常時表示）。

### 中立ペナルティ

- 善人陣営が中立を dead、悪人陣営が中立を alive にするとペナルティ。
- 未使用の生死カードを最大3枚ランダム破棄（残り3枚未満なら全て破棄）。キープでは発生しない。
- 発生時は専用ダイアログを表示。

### 終了・勝敗

- 両者の使用可能な生死カードが尽きたら終了（片方だけ尽きた場合はパス扱いで続行）。
- 終了時に未公開の人カードを全公開し、生存善人・生存悪人を数えて勝敗判定（中立は除外、引き分けは悪人勝利）。

## 今回のプロトタイプで簡略化した点

- **5枚シャッフル・スワップは未実装**。今回はシャッフル・スワップなしで、9枚ずつ配って開始します。

- 人カードの初期状態はすべて `alive`（`hidden` は将来用に enum のみ保持）。
- ローカル2人対戦は未実装（プレイヤー対 CPU のみ）。
- 素材は Flutter 標準のアイコン・図形・文字のみ（画像素材なし）。
- CPU は1種類（標準戦略）のみ。性格差分は未実装。

## ディレクトリ構成

ゲームルール（ドメイン / アプリケーション）と UI（プレゼンテーション）を分離しています。

```
lib/
  main.dart
  app/
    app.dart          … ルート Widget（MaterialApp.router）
    router.dart       … go_router のルート定義
    theme.dart        … ダークファンタジー寄りのテーマ・配色
  features/
    title/            … タイトル画面
    faction_select/   … 陣営選択画面
    rules/            … ルール画面
    result/           … リザルト画面
    game/
      domain/         … モデルと enum、定数（PersonCard, LifeDeathCard, GameState 等）
      application/    … ゲームロジック
        game_constants.dart      … 枚数・数値の一元管理（domain 側）
        game_setup_service.dart  … 配布・手札生成（将来のスワップ実装先）
        game_rule_service.dart   … パワー判定・効果・公開・ペナルティ・勝敗（純粋計算）
        game_engine.dart         … ターン進行の統括
        cpu_strategy.dart        … CPU 意思決定（CpuStrategy / CpuActionEvaluator）
        game_controller.dart     … Riverpod による状態管理
      presentation/   … ゲーム画面と関連ウィジェット
  shared/
    widgets/          … カード描画ウィジェット
    utils/            … アイコン・色・ラベル変換
```

ルールの数値・枚数は `lib/features/game/domain/game_constants.dart` に集約しています。

## 補足（実装上の仮定）

- **先攻はプレイヤー**固定としました（仕様に明記がないため）。
- 「キープはプレイヤーの操作対象が CPU 側のカードのみ」という UI 仕様に合わせ、キープは相手の場のカードを守る（＝相手に取られたくない状態を固定する）用途として動作します。
- CPU はゲーム上公開されている情報のみを用いて判断します（プレイヤー側カードの非公開情報は参照しません）。
- リザルトの「もう一度遊ぶ」は同じ陣営で再戦します。
